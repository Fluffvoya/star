# Git 工作规则

适用于所有任务。新任务开始前必读；推送前重新核对对应流程。

## 开始任务

- 先检查 `git status --short --branch`、当前分支和暂存区。每个新任务都创建并切换到一个新的任务分支，不在 `main` 上工作，也不复用其他任务的分支。通常从本地主分支创建；任务依赖另一分支时，按维护者指定的基线创建。
- 保留现有工作区、未跟踪文件和暂存区。若无法安全切换，停下来说明原因；不要为切换分支擅自 stash、reset、强制切换或清理文件。

## 暂存与提交

- 只有维护者明确要求时才执行相应的暂存或提交。没有此请求就不暂存、不提交；请求提交包含为该提交精确暂存相关路径，不包含推送授权。
- 使用 Conventional Commits：`type(scope): summary`，`scope` 可选；标题使用简洁英文祈使句，例如 `fix(scene): guard stale object handles`。有破坏性变更时，用 `!` 或 `BREAKING CHANGE:` 标明。
- 按逻辑变更拆分提交。每次提交只包含一个能独立说明的变更；该变更的代码、测试和文档可以放在同一提交。不要把无关修改、构建产物、本地缓存或敏感信息混入，也不要全量暂存。提交前复核暂存区，只提交明确属于本次变更的内容；如果无法与既有暂存内容安全分开，先停下说明。

- `.private-docs/` 下的内部文档一律不得暂存、提交或推送；不要用 `git add -f` 绕过忽略规则。

## 推送前

- 仅在维护者明确要求推送后执行。先获取目标远程的最新引用，例如 `git fetch origin`。核对本地 `main` 与远程 `main`（例如 `origin/main`）：本地主分支落后且可安全快进时，仅做快进同步；同步后两个引用必须指向同一提交。本地 `main` 超前、分叉、不能安全更新，或远程不可达时，不推送并报告。不要为对齐引用丢弃本地提交或更改他人的工作区。
- 确认任务分支当前没有未解决的索引冲突，再模拟将任务分支合入已同步的主分支，例如在任务分支运行 `git merge-tree --write-tree main HEAD`。不能把 `git diff --check` 或干净的工作区当作合并冲突检查。发现冲突、无法完成检查，或远程同名任务分支不能安全更新时，不推送并报告；不要擅自合并、变基或强推。
- 所有检查通过后才推送指定的任务分支，不推送 `main`。除非维护者另有授权，不改写已有提交、删除分支或推送其他引用。

PR、批准与签名规则尚未确定。交付前报告当前分支及是否暂存、提交或推送。
