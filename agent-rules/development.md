# 开发、架构与验证规则

适用于引擎实现、构建配置和测试任务。

- 实现方案与 ADR 是架构基线，按任务查阅 `docs/architecture/implementation-plan.md` 与 `docs/adr/` 中的相关条目。缺少所需决策时向维护者确认，不自行推断。不要把 `[建议]` 升为已确认决策，也不要自行实现 `[待定]`。变更 `[决定]` 前先由维护者确认，再同步更新方案和 ADR。
- 引擎、工具和游戏使用 C++23（如适用）及 CMake + Ninja；不添加 MSBuild 或 Xcode 构建链路。Windows x64、Linux x64、macOS arm64 是正式目标；Intel Mac 尽力支持。D3D11 是 Windows 1.0 的必验兼容后端。
- 项目由一人维护，使用本地验证，不引入 CI。运行仓库实际存在的检查和相关测试；报告测试结果以及未验证的平台。方案中列出的预设在脚手架建成前不是可用命令。
- 只改任务相关内容，保留用户现有改动。AI 生成的改动同样验证接口、线程与生命周期、跨平台行为和失败路径。
