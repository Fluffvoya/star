# ADR-0004：着色器语言

- 状态：已确认
- 日期：2026-11-20
- 关联：[Star Engine 实现方案](../architecture/implementation-plan.md) §2.1、§11.6、§12.6

## 背景

四个图形后端需要共享材质和渲染逻辑。为每个后端维护独立着色器会造成行为漂移、绑定布局重复实现和变体数量失控。

## 备选方案与后果

- GLSL、HLSL、MSL 分别维护。后端适配直接，但代码和功能需要重复维护。
- 只使用 HLSL 或 GLSL，再依赖翻译器。生态成熟度较高，但跨后端布局和语言特性受转换器限制。
- 使用 Slang 作为统一源语言。需要引入编译工具链和目标平台缓存管理，但可以共享模块、泛型和反射布局。

## 决定

使用 Slang 编写引擎和项目着色器。着色器编译器生成 SPIR-V、DXIL、DXBC 和 MSL，并输出绑定布局和反射数据。RHI 根据反射数据创建 PipelineLayout 和 BindGroup。

## 后果

ShaderCompiler 属于编辑器和工具侧。发布包携带目标平台所需的已编译变体和 PSO 缓存。每个目标后端必须单独验证编译结果，不能只验证源语言解析成功。

## 验收边界

M2 先验证 SPIR-V。M7 验证 DXIL 和 MSL。M10 验证 DXBC 及 Basic 绑定路径。编译失败必须保留明确的源文件、变体和目标后端诊断。
