# ADR-0009：游戏代码迭代

- 状态：已确认
- 日期：2026-11-20
- 关联：[Star Engine 实现方案](../architecture/implementation-plan.md) §2.1、§16；[ADR-0001](0001-gameplay-model.md)、[ADR-0011](0011-asset-formats.md)、[ADR-0017](0017-build-artifacts.md)、[ADR-0018](0018-implementation-baseline.md)

## 背景

游戏逻辑使用 C++，编辑器需要较快的代码迭代速度。动态库卸载会遇到对象、组件、任务、回调、反射缓存和线程局部状态的生命周期问题。

## 备选方案与后果

- 只重启编辑器。实现简单，但迭代速度慢且未保存编辑状态恢复成本高。
- 使用脚本或虚拟机替代 C++ 热重载。迭代快，但改变语言边界并增加运行时体系。
- 游戏模块动态库加快照式热重载。能够保留编辑数据和撤销记录，但需要严格的模块清理和失败回滚流程。

## 决定

游戏模块在开发配置中编译为动态库，编辑器在安全点执行热重载。引擎先捕获自有快照，再停止旧模块任务、清理实例和注册、卸载旧模块、加载新模块并恢复快照。注册、启动或恢复失败时回滚到旧模块和同一快照。第一版在 PIE 期间先停止 PIE，不迁移运行中的模拟状态。

快照只保存引擎拥有的自描述数据，不保存 DLL 内对象、地址或回调。未知字段和类型必须保留，无法恢复时进入恢复模式并保留副本，不覆盖源文件。

## 后果

模块 ABI、分配器、任务排空、回调注销和反射缓存清理都是热重载前置条件。热重载集成测试必须验证成功迁移、失败回滚、未知数据保留、撤销记录和旧模块无残留回调。

## 验收边界

M3 先验证游戏模块加载、注册和卸载。M5 完成编辑器内完整热重载和失败恢复验收。
