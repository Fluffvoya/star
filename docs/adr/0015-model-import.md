# ADR-0015：模型导入

- 状态：已确认
- 日期：2026-11-20
- 关联：[Star Engine 实现方案](../architecture/implementation-plan.md) §2.1、§10.3、§10.7

## 背景

资产管线需要导入现代开放格式和常见 DCC 格式，并将编辑期数据转换为统一的运行时网格、材质、骨骼和动画资产。

## 备选方案与后果

- 只支持 glTF。实现简单、格式清晰，但无法覆盖已有 FBX 资产。
- 依赖 Assimp。格式覆盖广，但体积、数据质量和平台维护成本较高。
- fastgltf 处理 glTF，ufbx 处理 FBX 和 OBJ。依赖职责清晰，需自行统一材质、坐标、骨骼和错误诊断。

## 决定

glTF 2.0 使用 fastgltf。FBX 和 OBJ 使用 ufbx。导入器只属于编辑器/资产管线，运行时只读取经过 Cook 的派生资产。导入结果必须记录源文件、导入设置、工具版本和依赖资产。

## 后果

导入器必须处理坐标约定、单位、材质、骨骼、动画和缺失资源。第三方解析库不能进入游戏 SDK 或运行时公共 API。导入失败不得生成可被运行时误读的空资产。

## 验收边界

M4 验证 glTF、FBX 和 OBJ 的网格、材质、骨骼及错误路径。导入结果必须能进入 DDC，并在源文件或导入设置变化时失效重建。
