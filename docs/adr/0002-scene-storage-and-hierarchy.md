# ADR-0002：场景存储与层级

- 状态：已确认
- 日期：2026-11-20
- 关联：[Star Engine 实现方案](../architecture/implementation-plan.md) §9.2、§9.6；[ADR-0001](0001-gameplay-model.md)

## 背景

场景需要支持稳定 GUID 查找、结构修改、对象删除和层级变换传播。把父子关系直接编码在对象容器中会使移动、删除和遍历顺序复杂化。

## 备选方案与后果

- 树形对象容器。层级访问直观，但对象移动和批量遍历成本高，结构修改容易影响迭代器。
- 每个对象保存父子指针。实现简单，但跨帧指针生命周期和删除传播容易失控。
- 平级对象存储加层级组件。对象管理稳定，层级计算由系统批量完成，需要额外的层级校验和遍历。

## 决定

每个 Scene 平级存储所有 GameObject。对象存储使用带代数句柄的 `SlotMap`，另以 GUID 哈希表提供稳定查找。父子关系使用 `Hierarchy` 组件表达，世界变换由层级系统按拓扑顺序传播。

## 后果

结构修改不依赖树节点地址。跨帧引用使用句柄或 GUID。层级系统必须检测父对象缺失、循环和跨场景引用，并在阶段边界统一处理结构命令。

## 验收边界

M3 必须覆盖对象创建、删除、句柄失效、GUID 查找、层级变换传播、循环拒绝和结构命令延迟提交。场景保存与加载必须保持 GUID、父子关系和对象顺序语义。
