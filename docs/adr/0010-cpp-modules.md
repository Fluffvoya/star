# ADR-0010：C++ Modules

- 状态：已确认
- 日期：2026-11-20
- 关联：[Star Engine 实现方案](../architecture/implementation-plan.md) §2.1、§5.4

## 背景

C++ Modules 能减少头文件重复解析，但三正式平台的编译器、标准库、构建工具和生成器支持仍存在差异。StarHeaderTool 第一版也以头文件 AST 解析为基础。

## 备选方案与后果

- 第一版全面使用 Modules。长期边界清晰，但会增加工具链兼容和生成代码的复杂度。
- 永久只使用传统头文件。短期稳定，但失去未来迁移和减少编译成本的路径。
- 第一版使用头文件和 PCH，同时保持模块化边界。当前稳定，后续可逐模块迁移。

## 决定

第一版不使用 C++ Modules。公共头文件、私有头文件和 PCH 作为构建输入。模块目录、公共 API 和生成代码保持可迁移到 Modules 的边界。

## 后果

CMake 不需要维护 BMI 或模块扫描规则。公共头文件必须独立可编译，传递包含和宏污染需要通过结构和检查控制。未来迁移不得改变运行时 ABI、反射元数据和序列化格式。

## 验收边界

M0 验证公共头文件独立编译。后续若启用 Modules，必须保留传统头文件消费者或提供等价迁移路径，并在三正式平台分别验证。
