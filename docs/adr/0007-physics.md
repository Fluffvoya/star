# ADR-0007：物理

- 状态：已确认
- 日期：2026-11-20
- 关联：[Star Engine 实现方案](../architecture/implementation-plan.md) §2.1、§13；[ADR-0001](0001-gameplay-model.md)

## 背景

引擎需要同时支持 3D 和 2D 物理、查询、碰撞事件和角色控制器。物理库必须覆盖正式平台并允许接入 Jobs 调度器。

## 备选方案与后果

- PhysX 同时承担 3D 和 2D。3D 能力完整，但 2D 需求、许可证和 macOS 支持不满足本项目取向。
- 自研物理。接口可完全定制，但开发和验证成本过高。
- Jolt Physics + Box2D v3。两者各自适合目标维度，接入层需要统一线程、查询和事件语义。

## 决定

3D 使用 Jolt Physics，2D 使用 Box2D v3。引擎提供统一组件、查询和事件边界，物理库对象保留在 Physics 模块内部。Jolt 和 Box2D 的任务提交通过 Star Jobs 适配，不创建独立线程池抢占核心。

## 后果

两套库的单位、过滤、生命周期和线程规则必须在引擎层统一。确定性要求、双精度配置和第三方编译选项必须在整个项目中保持一致。物理对象跨帧引用使用引擎句柄。

## 验收边界

M6 验证 3D 刚体、碰撞、角色控制器、关节、查询、事件和 2D 刚体、碰撞及查询。必须覆盖任务等待、对象销毁和场景卸载期间的资源清理。
