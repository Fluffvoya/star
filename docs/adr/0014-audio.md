# ADR-0014：音频

- 状态：已确认
- 日期：2026-11-20
- 关联：[Star Engine 实现方案](../architecture/implementation-plan.md) §2.1、§14.1

## 背景

引擎需要跨 Windows、Linux 和 macOS 提供设备输出、混音、总线、3D 声音和流式播放。音频基础设施应保持小型，并避免绑定某个平台的设备 API。

## 备选方案与后果

- 使用平台音频 API。控制力强，但三平台实现和设备行为差异大。
- 使用大型音频中间件。功能丰富，但许可证、部署和依赖成本增加。
- 使用 miniaudio。单文件、跨平台和许可宽松，但高级功能需要引擎自己组织。

## 决定

使用 miniaudio 作为音频设备和混音基础。Audio 模块提供音频组件、总线、3D 声音、流式播放和资源生命周期。混音在 miniaudio 管理的音频线程执行，游戏逻辑不直接操作音频线程状态。

## 后果

音频资源需要异步加载和引用计数。跨线程数据通过无锁或命令队列传递，禁止在音频回调中执行阻塞 IO、分配或复杂游戏逻辑。

## 验收边界

M6 验证设备初始化、总线、一次性播放、流式播放、空间化和资源释放。正式平台需要至少完成无输出设备和默认设备两类启动路径。
