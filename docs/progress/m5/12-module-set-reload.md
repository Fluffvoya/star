# M5-12 多游戏模块与整组重载

- 分支：`feat/m5-module-set-reload`
- 验证环境：Linux x64、`linux-dev`、llvmpipe Vulkan。Windows x64、macOS arm64 未验证。

## 交付

- `.starproject` 的 `Modules` 列表按依赖顺序排列，先列依赖项。Project Settings 可添加、移除及调整顺序。编辑文档、场景切换和 PIE 都按该顺序载入，世界按相反顺序卸载。
- Play > Reload Game Modules 在预检整个模块组通过后停止 PIE，捕获一次场景快照并切换整个模块组。第二个或后续模块失败时，释放已启动的候选模块，恢复原模块组和同一快照。
- 在场景之间切换时继续使用已验证的模块副本。重新编译产生的构建产物在用户执行重载时生效。`--game-module` 仍可显式覆盖项目模块列表。

## 验证

| 项目 | 结果 |
| --- | --- |
| `linux-dev` 构建及软件 Vulkan CTest | 19/19 通过 |
| 整组预检 | 重复模块 ID 在停止 PIE 前被拒绝 |
| 双模块失败回滚 | 首个候选成功加载，第二个启动失败后，两个原组件值、未保存改名及选择都保留 |
| 双模块成功迁移 | 同时注册两个独立模块，保留各自组件值，撤销仍可用。新 PIE 运行一帧只更新副本。 |

模块顺序来自项目设置。平台动态链接器解析共享库依赖，编辑器校验 Star 模块入口和 ABI。当前测试使用两个独立模块。
