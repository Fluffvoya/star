# M5-07 游戏模块热重载

- 分支：`feat/m5-game-module-reload`
- 验证环境：Linux x64、`linux-dev`、llvmpipe Vulkan。Windows x64、macOS arm64 未验证。

## 操作

以 `--game-module=<构建产物>` 启动编辑器。重新构建游戏模块后，在 Play 菜单选择 Reload Game Module。编辑器在构建产物同目录加载独立副本，保留动态链接器的相对依赖路径。构建目录需要允许写入。

## 交付

- 加载和 ABI 预检通过后停止 PIE。编辑器捕获包含未保存内容的二进制快照，在帧边界释放场景、系统和模块，然后从新模块重建场景。
- 成功后保留选中 GUID、脏标记和撤销/重做位置。新字段使用默认值，原有值按反射字段名或旧名迁移。无法解析的历史命令保留并报告。
- 候选模块注册、启动或恢复失败时，使用保留的旧模块副本和同一快照恢复。二次失败时进入恢复模式，把快照和诊断写入项目的 `Saved/Recovery/`，并禁止保存到源场景。重新加载可用模块可从内存快照退出恢复模式。
- 编辑世界与 PIE 各加载独立模块副本。PIE 在成功迁移或回滚后都保持停止，用户可重新启动。

## 验证

| 项目 | 结果 |
| --- | --- |
| `linux-dev` 构建与软件 Vulkan CTest | 19/19 通过 |
| 预检和回滚 | 无入口文件不停止 PIE。预检成功但启动失败的独立模块触发回滚，保留未保存值、选择、可执行的撤销与重做。 |
| 成功迁移 | 旧字段 `value` 迁移至 `points`，新字段取默认值。保留未知字段及组件，源场景未改写。迁移后可再次启动 PIE 并运行一帧。 |
| 二次失败与恢复 | 模拟旧副本缺失。Linux 验证旧映像已卸载、生成恢复快照及日志、成功重新加载后继续撤销。 |

本阶段覆盖独立游戏模块的一次手动重载及同进程恢复。自动构建、多个相互依赖的游戏模块与其他平台的加载路径尚未验证。
